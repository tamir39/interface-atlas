The material has a job

A little familiarity.
A clear boundary.

The binding holds an index and a writing page together. Offset edges suggest more leaves beneath. The metaphor helps you locate the note; it never stands in for an action label.

What makes this Skeuomorphism?

A solid cover surrounds a bound paper artifact: a separate stack of offset, edged pages, a ruled binding gutter, and four small CSS rings. These physical relationships carry the metaphor beyond a textured flat card.

The cover keeps the theme’s card geometry. The paper artifact explicitly uses 2px corners. Ordinary fields, actions, and index choices retain their theme geometry. Every word and control rests on an opaque Raised face, above and away from decorative layers.

What comes from the theme?

Palette, declared font stacks, and ordinary card/control corners come from each theme’s actual preview tokens. There is no universal brown paper or leather palette. This finite specimen does not load nine complete applications.

Editorial’s reading palette and type suit short notes. The bound notebook construction is an explicit material addition beyond its ordinary selective elevation.

What is applied, copied, and lost?

Each note keeps its own working draft while this page is open. Apply locally validates the title and text, then updates that note’s applied text and searchable index entry. Revert draft restores only the open note’s last applied text.

Search reads applied titles, text, and tags; it can hide the open note from the index without changing your open note or draft. Clear search restores the original index order. Download applied text creates a real UTF-8 text file of the open note’s applied text, even if its draft has changed.

No storage, account, backend, or synchronization is involved. Reload resets the entire demo. Applying locally does not create a durable save; a downloaded file is your manual copy.

What happens with device preferences?

Press feedback starts Off. On adds only 1px of downward press travel with a 120ms transform transition. Reduced motion and forced colors remove that travel. No page flips, delay, or drag action is simulated.

Forced colors removes decorative textures, shadows, rules, and binding chrome. System colors, explicit boundaries, Selected text, pressed semantics, form errors, and keyboard focus remain. System appearance follows live device changes.

Where does the physical metaphor come from?

The Xerox Star team’s office metaphor is a historical precedent for familiar objects in interfaces. Apple’s iBooks is a later bookshelf-and-book example. These are distinct historical references, not a sole-inventor claim or a visual template.

The Fieldbook layout, notes, CSS material, and interaction code are original Atlas work. No Xerox or Apple interface, screenshot, texture, component code, font file, or other asset is copied. Read the style source notes for attribution and reuse boundaries.
