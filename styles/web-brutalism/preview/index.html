01 / Structure

Document order is the first layout

Before drawing a column, put the page in reading order. Start with its name, explain its purpose, then place the action beside the information needed to choose it. Read the source from top to bottom. It should sound like one conversation.

A narrow screen is a useful check: when columns become a line, does the explanation still arrive before the decision? Keep that relationship in the HTML. A visual arrangement can change with the available space without making the reader reconstruct the sequence.

02 / Forms

A label stays when the field fills

A field needs a name that survives typing. Place a visible label beside it and connect the two. Use a hint for an example, a limit, or a reason for asking. A placeholder can offer a small prompt, but it disappears precisely when someone may need to check their work.

When an entry needs correction, name the problem next to that field and keep the entered value. A helpful message says what a valid answer needs. After a failed submission, move attention to the first field that needs work so the next step is close at hand.

03 / Navigation

Let the link name the destination

A link is a small promise about where a reader will go. Write its name with the destination in mind: the release notes, the delivery address, the full article. Repeated invitations such as “more” make sense only while their neighboring text is still in view.

Keep ordinary navigation ordinary. A real address can be copied, opened in another tab, revisited, or reached through browser history. Within a long document, a fragment gives a heading an address. The reader should be able to follow it and return without learning a separate navigation system.

04 / Typography

Set the measure, then read a paragraph

A type sample is easy to admire and easy to misjudge. Put a whole paragraph in the chosen face. Read across a line, find the start of the next one, and pause midway. Comfortable type gives the eye enough room to resume without hunting.

Try a long heading, a familiar sentence, and a word that will not break conveniently. Then narrow the page and enlarge the text. Keep the body measure modest, let headings wrap, and leave enough space between ideas to show their relationship. The exact font available on a reader’s machine may differ from yours.

05 / Recovery

An empty result still has a next step

An empty list can mean several things: nothing has been added, a filter matched nothing, or the page could not obtain its data. Say which condition the interface actually knows. A calm explanation is more useful than a decorative blank space.

Keep recovery near the explanation. A clear-filter action can restore the list while preserving the reader’s selections. If work exists outside the visible results, say so. A temporary search should not silently erase a decision made before the search began.

06 / Motion

Feedback does not have to travel

Begin with the still version of an interaction. A checkbox shows its check, a message names the result, and an active control can underline its words. These cues let someone understand what happened without following an object across the screen.

If movement adds useful context, make it a small, deliberate choice and respect the device preference. A reduced-motion view still needs the same facts and actions. On this page, optional feedback changes only a border’s color; the document, links, and controls keep their positions.

About this document

Why this is a Web Brutalism study

The document and its addresses are the structure: a numbered index, headings, complete articles, visible links, native controls, and thin rules. There are no stacked display cards, thick outlines, offset shadows, or decorative hero artwork. This is one content-first raw document variant; experimental and more expressive branches of the family are outside this preview’s evidence.

What the theme contributes

Editorial contributes its warm palette and serif display stack. This raw document explicitly replaces its rounded geometry and selective elevation with square, shadow-free document structure.

All 15 projected source variables remain available, including the unmodified card and control geometry values. This variant uses 0px for every actual corner, Ink for focus, and Primary / On-primary for the download action.

Declared body stack:Manrope, "Segoe UI", Arial, sans-serif

No fonts are fetched. Installed fallbacks and language coverage depend on the reader’s machine.

What the reading-plan tools do

The optional filter searches only index titles, topics, and summaries. It never hides an article. Native checkboxes keep their selection when a row is filtered out; the count reports how many selected notes are hidden. Download includes every selected original note in document order, with the trimmed plan title and public note addresses.

The title requires 3–48 characters after trimming spaces. A real UTF-8 text file named open-index-reading-plan.txt is created in the browser. User text is plain text. Nothing is sent, stored, synchronized, or saved in this page after reload.

Motion and system colors

Border feedback starts Off. On allows a 100ms border-color transition from Border to Ink on hover. There is no movement, animated shadow, entrance sequence, or smooth scrolling. Active action words underline immediately. Reduced motion and forced colors remove the transition.

Forced colors uses system document, link, and control colors. Native checkbox checks, visible links, boundaries, errors, and focus remain available. System appearance follows live device changes.

Guidelines, directory, and original work

David Bryant Copeland’s Brutalist Web Design guidelines are a credited reference for this content-first branch. The Brutalist Websites directory records a broader, varied field. These references do not establish a single inventor or a universal recipe.

The Open Index layout, six notes, styling, and interaction code are original Atlas work. No source prose, code, page layout, screenshot, or artwork is copied. Read the style source record for distinct credits, source terms, and limits.
