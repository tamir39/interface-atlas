# Neobrutalism validation

The [composition evaluation](../../examples/neobrutalism-composition-evaluation/README.md) tested this optional treatment over bounded profiles of all nine existing Atlas themes on **2026-10-27**. The profiles retain actual palette aliases, named body/display/mono stacks and panel/control corners from existing preview CSS. They do not rebuild or revalidate complete themed applications.

With Node **v24.14.1** and headless Chromium **153.0.8010.12**, the actual corrected run passed **72 base states**, **144 measured interaction contexts** and **11 check groups**. The base matrix is nine profiles × light/dark × 320/1280px × motion off/on. Every profile/appearance also exercises selected, invalid, hover, active and four keyboard-focus controls. Computed profile values matched all 18 manifest sets, all nine source CSS fingerprints matched and the nine light profiles differed by real values. The [machine evidence](../../examples/neobrutalism-composition-evaluation/results.json) retains every context row, source identities, runtime/validator hashes, exclusions and the raw report hash.

Measured visible text stayed at or above **5.036:1**; fields and button boundaries at **9.504:1**; the **72 dedicated keyboard-focus contexts** at **9.504:1** against their adjacent parent. All base states kept opaque fills, 2px ink outlines, 4px/4px zero-blur shadows, 44px control areas and no whole-page horizontal overflow. Actual computed colors were composited through ancestor fills. Text needs 4.5:1, or 3:1 when large; necessary control boundaries and sampled external focus need 3:1. See the [browser method](../../examples/neobrutalism-composition-evaluation/design.md#browser-method) for field/button distinctions and exclusions.

Keyboard inspection, skip navigation, filtering and empty recovery, retained selected detail, associated form errors, valid local review and draft/filter/selection continuity across visual preferences passed. Live System appearance, actual optional press travel, OS reduced motion overriding On, narrow forced colors, no JavaScript and an aborted enhancement script also passed. Ordinary runtime exceptions, resource failures and external requests were absent. Static fallback leaves enhancement controls disabled and all ideas readable.

The first run exposed a real forced-color defect: the heading period used system ButtonFace as a foreground on Canvas and became invisible at 1:1. An explicit CanvasText override repaired it without changing source colors or excluding the text. The [trial record](../../examples/neobrutalism-composition-evaluation/trials.md#failure-repair-and-visual-inspection) records that failure, correction and bounded visual inspection. Raw reports and ten screenshots remain temporary; the published text records fingerprint the final LF runtime bytes.

Design fit remains a separate decision. Play has the strongest affinity, retaining its rounded corners and typography while deliberately adapting its source shadow offsets. Blueprint, Botanical, Editorial, Layered and Pulse need a scoped adaptation. Gallery, Precision and Swiss conflict with persistent hard depth as their normal resting surface language. [Per-theme decisions](../../examples/neobrutalism-composition-evaluation/design.md#fit-decisions) cite the actual theme rules.

Limits: Chromium only; no screen reader, physical device, other engine, native zoom/text enlargement, real backend or performance benchmark. Named font binaries, imagery fidelity, native popup/validation UI, placeholders, decorative/SVG content and antialiasing are outside measured scope. This is bounded implementation evidence, not full accessibility conformance or universal theme compatibility.
