# Hero composition recipe

Revision: **0.1.0-draft**. Original Atlas synthesis. Use for an unresolved opening-section decision. The [source record](sources.md) identifies selected references; [preview notes](preview/README.md) describe the original specimen.

## Give the opening a task

Identify who arrives, what they need to recognize and the next useful decision. Express a concrete page or product promise with enough context to judge it. A large display heading can lead attention, but it cannot supply missing meaning. Use owner-provided facts or clearly identified original sample content; avoid invented customers, performance figures, awards or social proof.

Choose supporting content by its contribution. A short description can explain scope, an image can show the real subject and a small fact can reduce uncertainty. Repeated decorative copy or a dashboard-looking illustration should not imply capabilities the product does not have. Clearly distinguish a conceptual illustration from a working control or real product evidence.

## Make routes understandable

Give the principal route a predictive label and a real destination or implemented action. Use a link for navigation and a button for an operation. Supporting routes should have a distinct purpose; visual hierarchy need not make them hard to find or use.

A destination lower on the same page should have a stable, meaningful fragment target. Preserve ordinary URL and browser-history behavior unless an actual product need justifies another contract. Do not turn a route into a nonfunctional prop for a screenshot. If a required destination or service does not exist yet, resolve that capability or label the fixture boundary rather than implying the action is available.

Give controls accessible names, visible focus and useful target spacing. Keep their wording specific when the heading is absent from the visible region. A hover effect or decorative arrow supports a route; it does not create its purpose.

## Establish content and visual order

Choose heading levels from the page's structure. An opening title is commonly the page heading; a hero embedded in a specimen or larger page may have a different level. Visual size and heading level serve related but distinct needs. Keep the meaningful text order understandable in the document and when styles fail.

Arrange the opening message, supporting context and routes as a coherent group. Add a second column, background illustration or proof panel only when it helps the brief. The theme contributes its type, palette, shape and density. An optional material or composition style can change that treatment, with explicit scope and reasons for overrides. A component reference's hero does not automatically become the project's theme or design system.

Resolve text measure, heading wrapping, spacing, foreground/background pairs, focus values and meaningful media size against real content. If expressive art sits behind the text, inspect its possible backgrounds or provide a reliable readable face. Decorative media should remain outside the semantic explanation when it adds no information. Use an appropriate text alternative for meaningful media.

## Apply content pressure before fixing breakpoints

Check the actual title, supporting copy, route labels and necessary facts. Try a longer phrase, a long unbroken value when relevant, translated labels or fallback fonts appropriate to the project. A fixed-height frame that clips the useful message is not a complete responsive contract.

Let the layout adapt to available space and content while keeping the intended order. Keep every essential route available when columns stack. Use explicit overflow rules for media and long text rather than clipping the page. A narrow screenshot alone does not demonstrate enlarged text, zoom, right-to-left layout or all language support; name performed and missing checks.

Motion is optional. Give any chosen entrance or background effect a task-related purpose and a preference fallback. Keep the opening readable and actionable when it is reduced, off or unavailable. A page must not wait for a decorative animation before exposing its promise or routes.

## Handoff and reference

Record the accepted promise and facts, content order, destination/action contract, heading structure, media purpose, theme/style preservation or overrides, semantic values and adaptation behavior. Existing project components and routes remain the implementation starting point. A bounded improvement does not require building a new landing page or design document.

The [original preview](preview/index.html) uses a fictional Weeklight introduction beneath the lab's own page heading, so the specimen hero has an h2. Its Explore the example and See layout decisions links lead to real fragment sections. Split/stacked layout and long-content controls apply pressure without changing the route contract. All fixture choices are page-local and reset on reload; the native fragment routes remain usable without scripts. The neutral specimen's values are illustrative, not nine theme projections or a new global theme. [validation.md](validation.md) records actual coverage separately from source reasoning, user research and conversion outcomes.
