# P0 chapter review and design-document trial protocol

Frozen on 2026-10-15 before fresh generation outputs. User scope: review/fix P0 chapters, rerun consumer-app/storefront/bilingual-service design.md trials, report before any skills implementation. This is a qualitative document exercise. No product UI, browser/AT/service tests, skill changes or publication are authorized by this protocol.

## Review and generation procedure

Three isolated reviewers inspected state/recovery, forms/navigation and uncertain outcomes. Root consolidated six unique findings and revised the three chapters to 0.2-draft before generation. Reviewers confirmed their findings closed. Primary source facts and new Atlas policy proposals remain distinct.

The consumer and storefront briefs retain the exact bytes of the prior assessment. This protocol permits relevant revised P0 chapters even where earlier procedural wording omitted that route. Bilingual service is a new fictional brief derived from the earlier service scenario. Each fresh-context generator follows the unchanged Atlas preparation skill, compares 2–3 candidate READMEs, reads one selected detailed theme package, relevant motion/effects and knowledge, and the unchanged template. No earlier generated designs/evaluations, other trial outputs, installed global skills, external web sources or assets are generation input. Theme choice remains open.

Generators receive only their brief and reading/output procedure, not root review findings or rubric answers. The P0 chapters themselves include earlier consumer/storefront counterexamples; these are rehearsals of known briefs, not held-out or blinded evaluations. Bilingual service tests transfer to a new document brief; it has no prior generated baseline. Guided access to the knowledge index is explicit here and does not prove unchanged skill auto-discovery.

Use the supplied read helper for every repository content read. It records first-read order, purpose, returned UTF-8 bytes/hash and complete source-file bytes/hash before display. P0 source-ledger heading lists and selected source cards are allowed, with reproducible selectors. Whole-file and excerpt bytes are distinguished; repeated reads count. Log the brief separately. Directory listings and metadata hashes are not content reads. External URLs are inherited provenance, not freshly checked generation evidence.

Each generator writes only staging brief.md, first-draft.md, design.md, evaluation.md and read-log.json. First-draft.md equals design.md on delivery and stays immutable. Root hashes it before review. Findings and any later repairs are recorded separately; never replace first-pass evidence silently. Aim for 2,000–3,200 words as needed, prioritizing self-contained decisions.

## Frozen criteria

Use the original C01–C12: brief fidelity; theme selection; self-contained visual rules; state ownership; recovery; end-to-end tasks; adaptive/keyboard behavior; appearances/motion; content/assets; provenance; validation honesty; selective loading. Results are Document-covered, Partial, Missing or Open contract. External font/schema/service/translation dependencies remain separately gated even when the design discusses them correctly.

Additional targeted traces:

| ID | Trace when applicable |
| --- | --- |
| T01 | Save/request success followed by transaction failure; candidate A completes after edit B; no early Saved or lost B |
| T02 | Missing versus denied, malformed or unknown-version data; ordinary editing cannot overwrite uncertain authority |
| T03 | Two-context same-base edits and conflict during review; reset/import followed by stale queued writer; enforceable boundary or accepted loss |
| T04 | Largest valid created state fits compatible export/import; failed restoration retains previous authority |
| T05 | Pending control, validation ownership and dirty exit; usable feedback, focus, discard scope |
| T06 | Back/Forward, review Change, branching and locale switch; retained answers and defined history/focus |
| T07 | Applied remote effect, lost reply, reload; recovery identity acknowledged before dispatch or independent discovery |
| T08 | Duplicate activation, changed payload/intent, expired dedupe and delayed earlier-attempt reply; overlapping unresolved actions gated |
| T09 | Cancellation/completion race, stale or partial evidence, prolonged observation; truthful scope and bounded checking |
| T10 | Actionable project proposals versus unresolved external capabilities, without fictional endpoints or guarantees |

Not applicable requires a brief-specific reason. An open contract needs an owner/input and an implementation gate. Agents may propose local schemas/capacity policies if labeled; they cannot invent verified backend behavior. Root independently reviews all outputs against these frozen criteria; sibling review supplements it.

## Evidence and comparison limits

Compare new consumer/storefront first passes separately with earlier first-pass findings and earlier root-corrected documents. Do not count already-corrected behavior as a newly measured gain. Targeted traces are a diagnostic extension, not an historical score. Fresh agents, added knowledge, changed wording and familiarity all vary; no causal/statistical claim follows. File bytes are a reading-scope proxy, not actual tokens, latency, billing or usability.
