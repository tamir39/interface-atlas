# Claymorphism composition: evaluation design

## Bounded question

Can an optional inflated, softly shaded surface treatment support a small creative-session choice and validated local review across nine existing theme profiles, while keeping actual browser behavior distinct from design fit?

The original specimen is one local practice picker and session form, not nine rebuilt applications. A browser pass supports only its recorded composition and states. It neither validates complete themed apps nor establishes accessibility conformance or universal style compatibility.

## Preserved values and explicit shape departures

The generated [manifest](../../styles/claymorphism/preview/theme-tokens.json) preserves 15 source variables: page, surface, raised/panel, ink, muted, primary/on-primary, necessary border, focus, error, body/display/mono stacks, and panel/control corners. It records actual source CSS hashes, exact light/dark values and explicit role mappings. Named font families can resolve to installed fallback faces; no font binaries are bundled or fetched. The profile's retained corner variables remain identifiable even where this style deliberately overrides their use.

Selected expressive wrappers use an original **28px outer radius, 12px material frame and 16px inner radius**. This is a real geometry override, including for Play's 30px panels and Botanical's alternating corners. It is not preservation of every theme's original shape. An opaque outer Surface carries soft external and opposing inset shadows; its direct opaque Raised child covers every readable text node, decorative text mark and control. Selected choice content uses the verified Primary/On primary pair. Shadow planes remain below the opaque content, outside readable regions. Ordinary native selects and text/number fields keep each source profile's control geometry and a real necessary border. Dense work, imagery and the complete theme's layout are outside this example.

Shadows do not establish a field boundary, selected state, focus or validation. Selection has `aria-pressed` and persistent Selected text; a separate outline identifies the selected shape. Keyboard focus uses a separate external outline. Errors expose associated text and invalid state. The local review is a snapshot of valid input and hides when the relevant input or practice changes. It does not save, schedule, book or run a session.

Motion is off by default. Optional On allows only a 1px vertical press over 120ms using transform; meaning and validation remain immediate. OS reduced motion and forced colors remove the press offset and transition. Forced colors substitutes system roles and removes decorative depth, including ensuring visible decorative heading marks keep a readable foreground. Runtime controls begin disabled; no JavaScript or an aborted script leaves readable static content and native documentation links.

## Fit decisions

These judgments inspect actual theme specifications and geometry. “Adapt” requires a bounded, documented departure. “Conflict” rejects inflated clay as the normal surface language; a project exception still needs a reason and its own rendered checks. Every profile shares this specimen's layout and altered expressive geometry, so no row claims a complete unchanged theme.

## Browser method

The base matrix is **72 states**: 9 actual profiles × explicit light/dark × 320/1280px × motion off/on. All 18 computed profile value sets must match the manifest exactly, all nine source CSS hashes must match and the nine light profiles must differ by values. Nine labels over one palette cannot pass.

Each base state measures visible HTML text, enabled native fields/buttons, 44px control areas, whole-page horizontal reflow, opaque material/content fills, 28px/16px shape overrides, 12px material-frame spacing and ordinary field geometry. Every light/dark profile also receives selected, title-invalid, minutes-invalid, hover, actual active-off and active-on contexts, plus keyboard focus on theme select, title field, practice choice and review button: **180 interaction contexts**, including **72 dedicated keyboard-focus contexts**.

Contrast uses WCAG 2 sRGB relative luminance from actual computed foregrounds, fills and borders. Transparent ancestor fills are composited to an opaque page. The measured path rejects background images, whole-element opacity, filters and blend modes. Normal text needs 4.5:1; large text needs 3:1. Fields require a real border with 3:1 against both field fill and adjacent parent. Buttons need a border or fill with 3:1 against the adjacent parent. Keyboard outlines need at least 2px width, 3:1 against the adjacent parent and no clipping by overflow-hidden/clip ancestors.

**Inset box shadows are not RGB backgrounds.** The arithmetic alone cannot establish contrast where shadows paint over text. Structural checks therefore require each clay wrapper's direct opaque, shadow-free content child, readable descendants inside that child, the reserved material frame and no generated text overlays. The opaque child paints above its parent's inset shading. Temporary screenshots receive bounded visual inspection for shading placement, readable content and unclipped focus. This is structural/computed evidence with manual observations, not a pixel-by-pixel contrast audit of every antialiased edge.

Hidden/placeholder text, native select popups and browser validation UI, glyph internals, SVG paths and antialiasing are excluded. Visible decorative HTML text is included, including forced colors. The 44px target is Atlas's comfort goal. These finite checks are not complete accessibility conformance.

Additional trials assert native labels/landmarks, skip navigation, Space selection, trimmed title length 3–48, integer 5–120 minutes in steps of 5, associated errors, valid local review, preference/input/selection continuity, stale-review invalidation, reset recovery, live System appearance, reduced-motion and forced-color overrides, no JavaScript and aborted initialization. Runtime files are served under a loopback subpath. Ordinary exceptions, failed resources and external requests must be absent; intentional aborts are separate. Repository/build checks handle neighboring documentation links.

The temporary raw report retains every measured element and context. The checked-in machine record compactly projects the actual run while preserving every state row, identity, source and runtime/validator hash, exclusions, group observations and raw-report SHA256. Temporary screenshots remain outside the repository. Source-based fit remains separate from a passing browser matrix.
