# Neobrutalism composition: evaluation design

## Bounded question

Can an optional opaque treatment with firm ink outlines and hard offset depth remain useful on nine existing palette, font and corner profiles, while preserving an honest distinction between technical behavior and theme fit?

The shared specimen is a local idea board with filtering, persistent inspection context and a validated local brief. It is not nine rebuilt applications. A browser pass supports this composition and its measured states; it does not validate all existing themed apps, establish accessibility conformance or make Neobrutalism a suitable default for every theme.

## Preserved roles and explicit departures

Each generated profile retains 15 variables: page, surface, raised/panel, ink, muted, primary/on-primary, necessary border, focus, error, body/display/mono stacks, and panel/control corners. The [manifest](../../styles/neobrutalism/preview/theme-tokens.json) records source files, SHA256 identities, exact light/dark values and explicit aliases for missing roles. Theme credit records remain authoritative. Named stacks may render local fallback fonts; no font binaries are shipped or fetched.

Neobrutalism adds opaque fills, 2px ink outlines and a 4px/4px hard offset shadow with zero blur to selected first-level surfaces. These are original Atlas composition choices, not extracted defaults for every theme. The existing `--border` and `--focus` roles remain identifiable; choosing ink for the style boundary is a documented role substitution, not a rewrite of the source palette. The uniform shadow also deliberately differs from Play's 4px/5px panel shadow and Blueprint's low-alpha 5px/5px depth. Panel/control corners retain each profile's values instead of becoming universally square. Theme typography families retain their roles; this compact board does not reproduce the source app's complete heading scale or layout.

Useful content, status, validation and focus do not wait for animation. Motion-off is immediate, and OS reduced motion overrides an explicit On choice. Forced colors replaces style colors with system roles and removes decorative depth. Enhancement controls begin disabled; without JavaScript or after an aborted script, every static idea remains readable and useful documentation links remain native.

## Fit decisions

“Adapt” requires a bounded, recorded departure from the theme. “Conflict” rejects this treatment as the normal resting surface language; an exceptional project treatment still needs its own rationale and rendered checks. No row claims an unchanged complete theme: all nine share the specimen's board layout and added surface treatment.

These decisions inspect the actual theme specifications, not only names, screenshots or palette similarity. Their linked sections also identify source observations versus Atlas proposals. The [style source record](../../styles/neobrutalism/sources.md) credits conceptual references independently from the original preview and validator.

## Browser method

The base matrix contains **72 states**: 9 profiles × explicit light/dark × 320/1280px widths × motion off/on. It records actual computed values for every profile and compares all 18 light/dark identity sets with the manifest. All nine source CSS fingerprints must match; nine labels over one palette cannot satisfy the check.

Each state measures visible HTML text, enabled field/button boundaries, 44px control areas, whole-page horizontal reflow, opaque fills, 2px outlines and absence of backdrop blur. Separate light/dark runs across every profile measure selection, invalid form, hover, active and keyboard focus on the settings select, title input, inspected card and submit button: **144 interaction contexts**. Relevant `aria-pressed`, selected text, error association and local behavior are asserted rather than inferred from changed root attributes.

Contrast uses WCAG 2 sRGB relative luminance with the actual computed foreground/background colors. Transparent fills are composited through ancestor fills to the opaque page; the measured path rejects background images, whole-element opacity, filters and blend modes rather than silently assuming a safe color. Normal text needs 4.5:1 and large text 3:1. Native field borders need 3:1 against both their fill and adjacent parent; buttons need a border or filled shape at 3:1 against the adjacent parent. The latter permits a verified filled primary action whose ink border is close to its own fill. External keyboard outlines need 3:1 against the parent surface, at least 2px width and no clipping by overflow-hidden/clip ancestors. This does not test every possible adjacent pixel or native popup menu.

Hidden text, placeholders, native select popups and validation bubbles, glyph internals, SVG/decoration and antialiasing are excluded. The 44px target is Atlas's comfort goal. No complete accessibility conformance is claimed.

Additional trials exercise native labels/landmarks, skip navigation, Space selection, search and category filters, empty-result recovery, selected detail retained when filtered away, local brief validation/review, draft/filter/selection retention across visual preferences, live System appearance, reduced motion overriding On, narrow forced colors, no JavaScript and an aborted enhancement script. Ordinary runtime errors, failed resources and external requests must remain absent; the intentional script abort is recorded separately. Runtime files are served under a subpath. Documentation links are handled by repository/build checks rather than the isolated preview server.

The raw report retains every measured sample and context. The checked-in machine record is a compact projection of that actual run, preserving every state row, identity, source and tested-file hash, exclusions, group observations and the raw report's SHA256. Screenshots stay in the temporary run directory; visual inspection is a separate bounded observation.
