## Local proposals

Precision is selected as a fit hypothesis. Local decisions include inline proposal editing/review, separate per-field inclusion, immutable review/action snapshots, explicit revision comparison, persistent attention inside the request list, stable list ordering during interaction, a proposed 960px list/detail breakpoint, 44px action targets, immediate motion-free feedback, and a 10-second local delayed-observation message. None is represented as user research, an existing product rule or a working service capability.

State decisions keep execution, attention, pending command and connection separate. Edits after dispatch cannot change the submitted scope; overlapping new intent waits for reconciliation. Lost replies do not permit blind resubmission. Cancellation requests do not establish a stop, and stopped/completed work may retain earlier effects. Reversal requires a fresh supported action rather than an assumed Undo.

## Open inputs and gates

Live effects remain unavailable until product/security owners define actual operator identity and authority; proposal owners provide version/evidence contracts; integration/execution owners define exact effects, atomic revision preconditions, action/attempt identity, duplicate prevention, terminal/partial outcomes and ordering; recovery owners provide independently recoverable lookup and missing/expired meanings; cancellation owners specify scope, race behavior and acknowledgement/stop evidence; application owners define durable draft/recovery storage and loss limits. Observation pacing, a real reconciliation route, supported browsers, assistive technologies and licensed font packages are also open. These responsibilities are proposed, not assigned people or invented endpoints.
