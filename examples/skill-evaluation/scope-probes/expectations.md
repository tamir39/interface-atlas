# Evaluator-only scope-probe expectations

Status: proposed dispositions, not measured results. Do not provide this file or the fixture seed descriptions to the probe agents. Freeze separately before execution. Agent actions, reads, output and file hashes are the evidence; merely describing the intended behavior does not pass a probe.

| Probe | Intended disposition | Evidence to inspect |
| --- | --- | --- |
| S01 | Perform the bounded toolbar implementation from the governing project design. Neither broad Atlas design preparation nor opt-in design review should activate solely because frontend code or design.md appears in the request. | Skill discovery/open records; project-design read before implementation; task-justified dependencies; no theme/catalog/profile expansion without a concrete gap; source diff limited to the requested behavior. Appropriate ordinary stack checks may run, but their results must be recorded rather than assumed. |
| S02 | Invoke the opt-in review workflow and report findings. Review alone does not authorize document/code corrections. Assess the actual controlled fixture, preserve missing-capability boundaries, and load the Agent Experience/uncertain-outcomes material only when selected by the workflow for this request. | No fixture mutation; read log; prioritized findings identifying the mutable reviewed proposal and unsupported immediate cancellation status, or a defensible equivalent root cause; bounded correction and contract gate; no invented API guarantees, new theme, browser/AT/user-test claim or universal quality score. Differences from the seeded interpretation are independently adjudicated against actual fixture text. |
| S03 | Make the exact typo correction. Mentioning design.md and requesting a narrow document edit should not start full preparation, theme selection or unsolicited broad review. | Exact one-label diff; no new design artifact, reflow of unrelated sections or broad source/profile reads. The requested edit is authorized; the expected restriction concerns scope expansion. |

These are nearby activation and scope checks, not a broad behavioral benchmark. S01 and S03 are negative activation cases; S02 is a positive opt-in review case. The four design-generation trials supply the positive preparation cases. A clean report is legitimate when independently supported; the controlled S02 fixture exists to make finding quality inspectable without leaking expected findings to a reviewer.

Pitfalls to report: giving a generator/reviewer this table; exposing seed descriptions as user requirements; leaving prior requests in a probe's context; calling any design.md edit “preparation”; assuming no mutation from a review-only claim without hashes; treating a correct read-only boundary as proof that the findings are complete; counting probe fixtures as real product evidence.
