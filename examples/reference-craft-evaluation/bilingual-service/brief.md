# Studio Request — fictional bilingual service trial brief

New trial input, 2026-10-15. This is a design-document exercise, not a request to build or submit to a real service.

A small community studio offers a restrained, approachable service-request web form in English and Vietnamese. Visitors choose a consultation or workshop, give contact details, enter relevant preferences, review answers, and submit one request. The workshop branch asks an additional group-size question; consultation does not. No final data model or field constraints are supplied; label proposed inputs and bounds as project proposals.

Visitors can return from review to change an answer, use step Back and browser Back/Forward, switch interface language while editing, and leave with unsaved work. Changing service can change relevant questions. Preserve understandable review/change context and distinguish final submission from Continue. Support keyboard use, phone-first layout usable on desktop, Light/Dark/System and reduced motion. A full-page flow is acceptable; modal editing is not required.

No backend/API/provider, account system, retention policy, session model, translation pack, real brand assets, font files or implementation stack is supplied. Durable save/resume and remote submission recovery are capability decisions, not established functionality. Distinguish retained draft, remotely accepted request and completed service/appointment. Connections and storage can fail; a lost response can leave an unconfirmed outcome. Do not invent working endpoints, reservations, successful submissions, support channels or authentication requirements.

Propose state ownership, navigation, validation/focus, branch/review, language and uncertain-outcome rules with specific external contract gates. English/Vietnamese translation availability needs a delivery policy; do not assume automatic translation of free-text answers. No payments, AI/agent controls, booking calendar, enrollment, marketing subscriptions or accounts are requested.

Use the unchanged Interface Atlas preparation workflow with relevant revised P0 knowledge. Compare 2–3 candidate READMEs; select one theme and embed its actual rules/tokens. Produce a self-contained design.md, requirement-to-heading evaluation, immutable first draft and contemporaneous reading log, with source creators/versions/terms and performed versus future evidence. No old generated examples, other trials, installed global skills, external web research, UI or runtime implementation are inputs.
