# Pocket Practice design

Status: proposed project specification, 2026-10-20; document preparation only. Theme: Layered 0.1.0-draft, original Atlas synthesis. Product facts come from the supplied fictional brief. All navigation, markup, data, persistence, capacity and editing choices below are project proposals, ready for implementation review rather than evidence of a working product.

## Purpose, evidence and direction

Independent learners should find a text lesson, make room for practice, record what they actually completed and return to it. The interface is English; authored Vietnamese lesson passages retain Vietnamese. There is no language toggle, account, synchronization, backend, AI or agent control. Same-browser reload persistence is required when storage works. No user research, product content, assets, fonts, implementation stack or final data model was supplied.

Choose Layered because comfortable controls and purposeful opaque planes fit repeated personal tasks. Botanical's reading emphasis and Play's expressive learning character were considered through their READMEs; Layered needs fewer visual adaptations for planning and settings. This is a design judgment, not a measured usability result. Retain Layered's palette, comfortable spacing and coherent rounded shapes; reduce its large display type for a phone application. Omit artwork, shadows, decorative effects and animated transitions. Use text and native controls without a component-library dependency.

## Information structure and content

Four ordinary link destinations appear in this order: **Lessons**, **This week**, **Completed**, **Settings**. The first visit opens Lessons. This week contains the goal, dated plan and recoverable unfinished edits. Completed contains only acknowledged completion records, newest first; planned work never appears as completed. Settings contains Appearance, browser-data status and explicitly destructive recovery controls.

Lessons orders content as heading, search/filter controls, result count, lesson list. Each row shows the full title, topic, summary and **Open lesson** link, followed by a separately labeled **Bookmark TITLE** toggle. Use no clickable outer card around nested controls. Filters are Search lessons, Topic and Bookmarked only; all combine. Search uses trimmed, Unicode-normalized, case-insensitive title/summary/topic matching without stripping Vietnamese accents. Empty search returns the full catalog. Filtering retains fixed authored order and does not clear bookmarks, plans or open lesson context. **Clear filters** resets all three and focuses Search lessons. Announce the resulting count politely after input settles for 300ms; focus stays in the control.

A lesson page orders title, topic, summary, full text and **Start practice**, with **Add to this week** and bookmark as supporting actions. Lesson content is semantic text, not uploaded HTML. Set document language to English and Vietnamese passages to `lang="vi"`; use safe text rendering for personal notes. Titles, summaries, topics, lesson bodies and stable IDs require a content owner's supplied catalog before implementation acceptance. No duration, difficulty, image or achievement claim is fabricated.

Use URL paths or equivalent ordinary destinations for list, lesson ID, week and completion ID; choose the routing technology with the eventual stack. Persist filters in URL query parameters and selected week as an ISO civil date. Invalid IDs show **This lesson is unavailable** with a Lessons link; missing completed records return a clear Completed-list recovery. New logical pages update the document title, scroll to the top and focus their heading. Back/Forward restores filters and prior scroll/focus where the target still exists; otherwise focus the destination heading. Do not add history entries for each typed character.

## Typography, geometry and adaptation

Use `"Segoe UI", Arial, sans-serif` initially. Plus Jakarta Sans is the optional intended family, normal 400/500/600/700, gated on selecting an exact licensed package and verifying Vietnamese glyphs. No font file or remote font service is supplied. Page headings are 1.75rem/1.25, weight 600; section headings 1.25rem/1.35, 600; lesson reading/body 1rem/1.6, 400; labels/metadata .875rem/1.5, 500; controls at least 1rem/1.5. Preserve normal tracking and user font settings. Reading measure is 65ch maximum; no essential text truncation or fixed-height lesson cards.

Use the 4/8/12/16/24/32/48/64/96px spacing scale: 8px label-to-field, 12–16px related actions, 24px panel inset and 24–32px between task groups. Narrow panel inset is 16px. Panels have 24px radii; fields/buttons 12px with 1px Border; dialogs 28px. No resting shadow. All controls and navigation targets have at least 44×44px usable areas. Focus is immediate 3px solid Focus with 3px offset; prevent clipping, and use system Highlight in forced colors.

Phone first: 16px page gutters, one content column, wrapping four-link navigation above main content, stacked full-width fields and naturally wrapping action groups. No fixed bottom bar. At 48rem, use 24px gutters and horizontal filter groups only when labels fit. At 64rem, move the same navigation to a 224px Low rail; main content remains in DOM order after navigation. Main shell maximum is 1200px. Catalog stays a readable list; the week is seven stacked day groups, optionally two columns above 64rem with chronological row order. Do not require dragging or a horizontally scrolling calendar. At 320 CSS px and 400% zoom, reflow to one column; allow content growth, errors and the onscreen keyboard without hiding focused actions. These thresholds are proposals requiring content-fit checks.

## State ownership and persistence

Propose IndexedDB local authority, with a single transactional boundary covering metadata, personal data and drafts. Bundled catalog is separately authored read-only content. Search, dialog state, scroll and Undo are transient; URLs own list filters and chosen week. Browser storage owns acknowledged bookmarks, plan entries, goal, completions, appearance and recovery drafts. Nothing is synchronized or guaranteed against browser clearing, eviction, profile/device loss or private-session termination.

Proposed version-1 envelope: a non-reused random `generation`, monotonically increasing `revision`, schema version, appearance enum, bookmarked lesson IDs, goal text/weekly target, dated plan entries, completion records and separately identified drafts. Plans contain ID, lesson ID, title snapshot and local `YYYY-MM-DD` date. Completions contain unique practice ID, lesson ID/title snapshot, optional originating plan ID, UTC completion instant, local date/zone offset and note. Never infer completion from a bookmark or plan. Current local dates determine the displayed Monday–Sunday week; stored civil plan dates do not shift on timezone changes. Historical completion date labels preserve their recorded local date.

Shared proposed limits apply at creation, draft recovery and every write: goal 1–120 Unicode code points, weekly target integer 1–7, note 1–500 code points, 500 bookmarks, 100 plan entries, 5,000 completion records and 20 drafts. Personal-data envelope plus drafts is bounded to 8MiB UTF-8 serialized size; actual browser quota may be lower. Validate IDs, unique keys, enums, dates, cross-references and bounded plain text. Do not delete history automatically at a limit. Explain the reached limit and offer review/deletion of chosen records or copying notes. Content IDs and catalog-change behavior need owner approval; retain historical title snapshots for unavailable lessons.

Main record changes use explicit Save; bookmark/appearance toggles are immediate transactions. Recovery drafts autosave after 600ms of inactivity, labeled **Draft saved in this browser** only after transaction completion. Until then show **Unsaved changes**. A recovered draft is offered with its lesson/editor context and **Resume**/**Discard draft**; never auto-apply it as completed work.

Bind every Save to immutable candidate A, its draft version and acknowledged base generation/revision. Serialize mutation dispatch. Transactionally re-read, compare generation/revision, validate and write; transaction completion alone permits **Saved in this browser**. Editing may continue during Save; if B follows A, acknowledge A while B stays dirty and the editor stays open. Clear only the exact submitted draft version; preserve a newer draft. All writer paths, including delayed draft writes and deletion/reset, check generation. No old completion may clean or resurrect a new-generation draft.

A stale revision rejects the change and preserves its draft: **Changed in another tab. Review the latest version before saving.** Show latest saved values beside the draft. **Use latest** starts from current authority; **Continue with my changes** opens a new review draft against latest, explicitly listing fields/records being changed, followed by another Save and transactional recheck. Never replay an entire stale envelope. Repeated conflicts repeat review. Cross-tab notifications improve awareness but are not the locking mechanism. Exact transaction behavior remains an implementation verification gate.

## Essential task transitions

**Bookmark:** toggle the lesson's saved flag; while pending show **Saving bookmark…** and suppress repeat activation across pointer/keyboard paths. On commit show Bookmarked/Bookmark; on failure retain the previous acknowledged state and a persistent **Bookmark was not saved. Retry** message. Empty Bookmarked only says **No bookmarks yet. Browse lessons to save one.**

**Plan:** Add to this week opens a named native dialog with the lesson title, native date input restricted to the displayed week and **Add practice**. Duplicate lesson/date is identified before confirmation with a link to the existing entry; different dates are allowed. Commit adds one entry. Move uses the same explicit date editor. Remove affects only that plan entry, not its completion; offer Undo for the latest acknowledged removal until another removal, route departure or reload. Undo is a checked inverse transaction and can fail visibly; disclose its lifetime beside feedback. Empty week says **Nothing planned for this week** with **Browse lessons**. Prior/next-week links carry real dates.

**Practice:** Start practice creates a unique draft identity; a failed draft write allows clearly labeled temporary work with **Copy note**, not a false saved indicator. The practice page keeps lesson text available, labels **Practice note**, explains the 500-character limit and uses **Finish practice**. Validate trimmed nonempty note on submission; preserve original entered text while correcting. Commit the completion and removal of its submitted draft together. Repeated Finish for the same practice ID returns the existing completion, never a duplicate. On acknowledged success open the completed record and focus **Practice completed**. If a newer note edit exists, remain in the editor and offer viewing the saved candidate separately. A linked plan entry gains **Completed on DATE** only from the committed record; unrelated entries remain planned.

**Goal:** This week shows saved goal and **Edit goal**. Edit copies goal/target into a draft. **Save goal** commits both together; Cancel preserves saved values. Blank initial goal prompts **Set a practice goal**, without implying a failed learner. Completion count is derived from actual records in the selected week, labeled **N completed practices**, not an invented score or streak.

**Revisit:** Completed groups actual records by recorded date, with lesson title, note excerpt and **Read practice**. Detail shows the full note and date; missing lessons retain title/note with an unavailable-content explanation. Empty history says **Your completed practices will appear here** and offers Browse lessons. Deleting a record requires **Delete this practice and its note? This cannot be undone.** Confirmed transaction deletes only that record, returns focus to the next record or list heading and recalculates counts. Failure leaves it visible and recoverable.

## Errors, interruption and recovery

Validate on explicit submit; show a length counter while typing without premature invalid errors. Use custom form feedback with native interactive validation suppressed for those forms, while retaining native field types and semantics. Errors associate through `aria-describedby` and `aria-invalid`; focus a linked summary after failed submit. Corrected fields clear their stale error. Storage errors never mark correct input invalid. Pending Save stays focusable with guarded `aria-disabled`; block duplicate clicks, Enter and alternate entry points. Status uses a polite live region; persistent failure text includes Retry and Copy note where applicable.

Dialogs have a name, deliberate first-field focus, native modality, visible Cancel and no outside-click dismissal. Clean Cancel/Escape closes and restores the opener. Dirty close switches the same dialog to **Keep editing**/**Discard changes**, focusing Keep editing; Escape there resumes editing. Forced closure preserves acknowledged recovery drafts; unfinished writes may still be lost. If modal support fails, use a full-page editor with the same draft rules. Route departure from dirty work offers Save, Keep editing or Discard; a browser unload prompt is supplemental and cannot guarantee mobile interruption protection. Reload restores committed records and acknowledged drafts only.

Startup distinguishes loading, absent record, valid record, blocked access, malformed data and unsupported newer schema. Missing data says **No saved practice data was found in this browser**; it does not assert first-ever use. During loading, keep navigation but disable mutations with a reason. On access denial, offer Retry and explicit **Continue temporarily**; show **Changes are only kept until this page closes**. Do not queue automatic replacement when storage returns: review temporary changes against newly read authority first.

On malformed/newer data, stop writes to that authority and preserve originals. Explain unreadable versus unsupported separately; offer Retry and copying readable draft text. A diagnostic download is offered only when raw records are actually readable, labeled **Diagnostic data; not a restorable backup**. Version 1 performs no guessed migration. A blocked database upgrade asks the user to close other Pocket Practice tabs and Retry. On full storage retain latest draft in memory, show **Not saved—browser storage is full**, and permit copying notes or explicitly deleting chosen acknowledged records; failed deletion/reset also retains authority. No claim of successful recovery follows merely from closing a dialog.

**Reset browser data** is secondary in Settings, requires review of affected bookmarks, plans, goal, history, drafts and appearance, and explicit confirmation. Reset atomically assigns a fresh generation and empty data; all old pending writers/drafts are retired. Failed reset reports failure and retains prior authority. No routine import/export or independent-backup promise is proposed. **Copy note** provides a bounded manual recovery path; general restore tooling would require a new format, capacity and replacement contract.

## Appearance, validation and open gates

Appearance is a native labeled Light/Dark/System choice; default System follows live OS changes. Restore a validated saved choice before paint where feasible. Failed preference writes retain a working current-session appearance with **Appearance changed for this visit; it could not be saved**. No flash-free guarantee is made. All visual state changes are immediate, including reduced-motion mode; no smooth scrolling, entrance, celebratory effect or animation runtime is selected. Preserve semantic landmarks, skip link, logical headings, native buttons/links, keyboard reachability and no hover-only information.
