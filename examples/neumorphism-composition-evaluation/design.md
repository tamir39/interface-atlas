# Neumorphism composition: evaluation design

## Bounded question

Can shallow same-surface raised/recessed material support a small reading-preset task across nine existing theme profiles, while keeping readable content, independent control semantics and source-based design fit explicit?

The specimen is one browser-local workbench, not nine rebuilt apps. It changes the displayed sample's name, maximum measure, font size and line height after valid Apply. Draft edits and invalid input preserve the last applied sample. Reset recovers the draft and sample together. The UI neither saves a preset nor changes browser/OS preferences. These finite checks establish neither complete theme compatibility nor accessibility conformance.

## Preserved values and material scope

The generated [manifest](../../styles/neumorphism/preview/theme-tokens.json) preserves 15 actual source variables: page, surface, raised/panel, ink, muted, primary/on-primary, necessary border, focus, error, body/display/mono stacks, and panel/control corners. Exact light/dark values, explicit mappings and source CSS hashes remain inspectable. Named fonts may resolve to installed fallbacks; no font binaries are bundled or fetched.

Neumorphic plane, host and face share one opaque Surface RGB. Only the bounded width choices and reading shell receive shallow paired light/dark shading; selected choices reverse apparent depth. The outer host retains the profile's panel radius, including Botanical's alternating 32px/8px corners. The 12px rim surrounds a direct opaque face whose corners derive independently as `max(0px, host corner - 12px)`; Botanical therefore becomes 20px/0px internally. A positioned shadow layer sits below that face. Every readable descendant belongs inside the opaque face. This is a same-material depth treatment, not inflated clay or a new universal radius.

Shadow alone conveys no control boundary or selection. Width buttons have a real necessary border, persistent Selected text/check, `aria-pressed` and an independent Ink outline. Focus uses a separate 3px outline with a 3px gap. Ordinary native fields and actions retain the source control radius; the primary action uses its source action/on-action pair outside the Neumorphic scope. Form errors expose associated text, invalid semantics and first-invalid focus. Name is trimmed to 3–48 characters, size is 16–24px in even 2px steps and line spacing is 1.5, 1.75 or 2.

Motion is off by default. On permits only a 1px vertical press over 120ms using transform. Shadows do not animate. OS reduced motion and forced colors remove the press and transition. Forced colors removes material shading and uses Canvas/CanvasText for neutral/selected content and ButtonFace/ButtonText for the primary action. Native system roles prevent the unreadable forced-color text backplates previously found in the separate Claymorphism evaluation. Runtime controls begin disabled; absent or aborted JavaScript leaves readable static content and documentation links.

## Fit decisions

These judgments inspect authored theme rules, independently of the browser matrix. Adapt means a bounded documented departure. Conflict rejects this material as a theme's normal working language; an explicit exception still needs its own reason and rendered checks. The specimen shares a layout and only 15 source variables, so no row establishes a complete unchanged theme.

## Browser method

The base matrix is **72 states**: 9 actual profiles × explicit light/dark × 320/1280px × motion off/on. All 18 computed 15-variable identity sets must match the manifest, all nine source CSS hashes must match and the nine light profiles must differ by actual values. Each base state checks visible HTML text, enabled fields/buttons, 44px control areas, whole-page horizontal reflow, same opaque Surface RGB across plane/host/face, retained outer corners, derived inner corners, a 12px rim, content containment and ordinary control geometry.

Every light/dark profile also receives selected, name-invalid, size-invalid, spacing-invalid, hover, actual active-off and active-on contexts, plus keyboard focus on theme select, name field, width button and Apply: **198 interaction contexts**, including **72 dedicated keyboard-focus contexts**. Native required/range/step flags, explicit overlong-name rejection, tampered select rejection, trimmed Apply, dirty/invalid draft continuity, preference continuity, a 48-character unbroken name and Reset are exercised separately. Additional trials cover skip navigation, Space selection, live System appearance, reduced motion, forced colors, absent JavaScript and an aborted initialization script.

Contrast uses WCAG 2 sRGB relative luminance from actual computed foregrounds, backgrounds and borders. Transparent ancestors composite to an opaque page. The measured path rejects background images, whole-element opacity, filters and blend modes. Normal text needs 4.5:1; large text needs 3:1. Fields require a real border at 3:1 against fill and parent. Buttons need a real border or fill at 3:1 against the parent. Selected outlines and keyboard focus need 3:1 against the parent; focus must be at least 3px with a 3px gap and must not be clipped by overflow-hidden/clip ancestors. The 44px target is Atlas's comfort goal.

**Box-shadow pixels are not RGB backgrounds.** Structural checks separately require the direct opaque shadow-free face, all readable descendants contained within it, 12px reserved rim, correct per-corner inset and face paint order above the shadow layer. Temporary screenshots receive bounded visual inspection for readability, shading placement and focus. This supplements computed evidence; it is not a pixel-by-pixel contrast audit of every antialiased edge.

Hidden/placeholder text, native select popups and validation bubbles, glyph internals, SVG paths and antialiasing are excluded. Visible decorative HTML text is included. The runtime is served under a loopback subpath. Ordinary exceptions, failed resources and external requests must be absent; the intentional script abort is recorded separately. Repository/build checks cover neighboring documentation links.

The temporary raw report keeps every measured element/context. Checked-in machine evidence is the validator-generated compact projection, preserving every context row, column schema, identity, source/runtime/validator hashes, exclusions, group observations and raw-report SHA256. PNGs remain temporary. Chromium is the only tested engine; no screen reader, physical device, native zoom/text enlargement, full app, backend or performance study is claimed.
