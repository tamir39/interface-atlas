# Coverage and preparation evaluation protocol

Evaluation date: 2026-10-15. Pinned Atlas revision: 782159e8e2510933c76989ff9fd9546d282c62cd. Scope approved: assess nine themes, run consumer-app and storefront document trials, report gaps and a prioritized skills roadmap before skill implementation.

This is a qualitative document evaluation. It produces no new product UI, usability test, production implementation, complete accessibility verdict, measured token/billing benchmark, or validated business workflow.

Keep the original five project families: portfolio/publication; SaaS/agent operations; image-led homeware storefront; creative community/learning; restrained bilingual service forms. Assess the calm consumer-app subcase separately within SaaS: 45 original-family theme pairings plus 9 consumer-app judgments. Theme fit is visual suitability with retained identity, not proof of product capability. Strong means natural visual fit, Adapt needs deliberate changes while preserving identity, Strained suppresses much of the defining visual language.

Two isolated-context agents receive fictional briefs and the existing preparation workflow. Each reads catalog, 2–3 candidate READMEs, selected detailed rules/sources, relevant optional motion/effects, and template. No other project examples, global installed UI skills, external research, or other trial outputs are loaded for generation. Trial requirements are authored evaluation fixtures; they are not confirmed requirements for a real user business. Record all repository content reads with order, purpose, UTF-8 bytes and SHA-256. Avoid inferring actual model token use, latency, billing or behavioral reproducibility from bytes.

Before reading final trial outputs, freeze these review criteria:

| ID | Criterion | Expected document evidence |
| --- | --- | --- |
| C01 | Brief fidelity | All fictional brief requirements preserved; additions and unknowns labeled. |
| C02 | Theme selection | Candidate comparison and retained identity; status remains draft. |
| C03 | Self-contained visual rules | Exact color roles/pairs, type, spacing, geometry, density, appearances embedded. |
| C04 | State ownership | Durable/session/draft/authoritative state and persistence failures resolved or explicitly gated. |
| C05 | Recovery | Pending, empty, unavailable, failure, repeated action, edit/discard and conflict behavior where needed. |
| C06 | End-to-end tasks | Key task paths and decision/state transitions are concrete; no invented service capabilities. |
| C07 | Adaptive and keyboard behavior | Content order, responsive/overflow rules, labels, focus and native semantics specified. |
| C08 | Appearance and motion | Light/Dark/System, reduced/off behavior, contrast scope, explicit optional effects. |
| C09 | Content and assets | Language, real media ownership/delivery and exact font-package checks relevant to brief. |
| C10 | Provenance | Theme/Atlas revisions, creator/source roles, original URLs, pins, reuse limits and adaptations. |
| C11 | Validation honesty | Document review vs inherited preview evidence vs future project checks separated. |
| C12 | Selective loading | Complete reading log; implementation should use the generated project document. |

Review outcomes are Document-covered, Partial, Missing, or Open contract. Open backend/asset/font contracts do not become passes for working functionality. All rendering, backend, assistive-technology and real product behavior remain untested in these trials. Preserve first-draft hashes and findings if review repairs any output. Root reviews both outputs independently of generation; sibling review can supplement it.

Use existing Atlas source records as inherited evidence. Do not present their external URLs as freshly reverified in this evaluation. Product-specific choices that lack a reusable Atlas chapter remain clearly labeled agent proposals. Roadmap priorities must link to these observed gaps and specify future knowledge chapters separately from thin actionable skills. Do not create or edit any SKILL.md, theme, template or runtime tool in this pass.
