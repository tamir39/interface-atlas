# Open Index composition design

This bounded reference applies the [Web Brutalism grammar](../../styles/web-brutalism/style.md) to **Open Index**, an original reading task containing six short frontend notes. Its content-first expression uses semantic document order, useful underlined links, native checkboxes, direct language, square sections and restrained 1px rules. It is one interpretation within a varied web practice, not a universal definition or a claim about a sole inventor. [Sources and credits](../../styles/web-brutalism/sources.md) separate the Atlas recipe from David Copeland's content-first reference and other research.

## Task and state contract

Six original articles use stable IDs: document-order, form-labels, link-names, reading-type, empty-states and motion-choice. Every article's complete text exists in the initial HTML and remains visible in the enhanced page. Native index anchors target those article IDs. No click handler intercepts document navigation, rewrites history or substitutes a panel; fragment URLs, Back and Forward are browser behavior. Scrolling remains immediate.

JavaScript enables settings, optional index search, checkboxes and a local plan form. Search hides matching index rows only, preserves their order and leaves all article text available. Empty results explain recovery. Clear restores the complete index. Filtering a checked row out does not uncheck it: visible status reports total selected and hidden selected counts, and export includes all chosen notes in document order. Checkbox accessible names identify the same original note before and after selection at the same viewport; native checked semantics carry state.

The reading-plan title contains 3–48 trimmed characters. Native required validation is supplemented by custom trimmed/minimum/maximum validity, including programmatic overlong values. Invalid submission focuses the first invalid field and exposes a nearby error through its description. The input intentionally permits an overlong draft so correction remains possible; successful export is the bounded action. A valid unbroken 48-character title must reflow at 320px. Typing, filtering and preference changes retain the raw title and all selections. With no selected notes the download button is disabled and a visible hint explains how to enable it.

**Download selected notes** creates `open-index-reading-plan.txt`. Its actual decoded UTF-8 bytes contain the trimmed plan title, chosen original article titles/topics/prose and canonical public source URLs for those notes. Hidden checked rows are included; unselected article content, interface chrome and private filesystem URLs are excluded. Accented text and literal markup remain ordinary text. The download neither edits the original articles nor creates a server-side record.

All enhancement state is page-only memory. Reload resets search, selection, title and preferences; an existing native fragment remains part of the browser URL. Without JavaScript or when initialization is aborted, every article, native link and disclosure remains readable and usable. Enhancement controls remain disabled with an explanation. No account, backend, remote resource, external font, physical metaphor, drag action or motion completion is required.

## Theme preservation and explicit overrides

The generated CSS/JSON adapter retains the same 15 root variables projected from nine actual theme preview stylesheets: Page, Surface, Raised, Ink, Muted, Primary, On-primary, Border, Focus, Error; body/display/mono families; panel and control radius. It records original source paths, creator credits and SHA-256 fingerprints. The browser compares all 18 light/dark computed identity sets against that manifest. Named font stacks may resolve to local fallbacks; no binary is fetched or claimed as verified.

Actual controls and content sections explicitly use **0px corners**, including all four individual computed corners. The source `--card-radius` and `--control-radius` values remain available as provenance but are unused by this composition. Thus Botanical's alternating corners, Editorial's rounded cards and input adaptation, and every other source geometry are deliberately overridden. Palette and typography retention does not cancel that departure.

Surfaces stay opaque and flat. There are no gradients, shadows, blur, textures, offset edges, transforms or decorative pseudo-elements. Links retain underlines; inputs and actions use real necessary boundaries; checkboxes keep native appearance and semantics. Native browser checkbox internals and popup paint can vary. The control/section corner check concerns actual computed authored geometry and does not claim identical native widget pixels across platforms.

Logical document order is retained when the layout stacks. Extended passages have a bounded reading measure; long titles and identifiers wrap. Fields/actions, index links, summaries and checkbox label areas meet a 44px comfort goal in this reference. Ordinary links within prose retain native inline behavior. Optional motion adds at most a 100ms border-color transition; it never moves content. Off is the default. Reduced motion and forced colors make transitions immediate.

## Browser method

The [optional validator](../../tools/validate-web-brutalism.mjs) serves the actual preview under a loopback subpath and uses an existing Playwright/Chromium installation. It records Node/browser versions, five runtime hashes, the validator hash, nine source fingerprints and 18 computed identities. A fresh temporary directory holds raw JSON, actual downloads and screenshots. The committed compact projection preserves every matrix/interaction row, its column schema, raw report hash/byte length and functional evidence; it does not distribute the large raw sample arrays.

The base matrix is nine profiles × light/dark × 320/1280px × motion off/on: **72 states**. Each profile/appearance receives checked, invalid-title, hover, pointer-active off/on and five keyboard-focus contexts: **180 measured interactions**, including **90 focus contexts**. Separate trials inspect native and trimmed bounds, maximum unbroken reflow, retained hidden selections, accessible-name stability, real file bytes, native fragment URLs and actual browser Back/Forward. Live System appearance, reduced motion, forced colors, JavaScript disabled and aborted initialization have dedicated checks.

Computed sRGB contrast follows actual visible text through ancestor fills and actual necessary control boundaries. Unsupported opacity, gradients, filters or blending in a readable path fails. Normal visible text needs 4.5:1 and large text 3:1. Fields need real 3:1 boundaries against both fill and parent; actions need a real boundary or fill at 3:1 against their parent. Keyboard focus requires at least a 3px outline, 3px offset, 3:1 adjacent contrast and no ancestor clipping. All visible HTML text is measured, including heading punctuation and fallback explanations.

Checks separately inspect every actual control/section corner, paint, underlined named links, native article visibility, target area and whole-page reflow. Native checkbox labels supply their target area. Checkbox glyph internals, native select popups, native validation bubbles, antialiasing and hidden/placeholder text are outside arithmetic. Bounded screenshots supplement the measured paths, particularly forced-color native checkbox, title and primary-action pixels.

Forced-color assertions create probes for **Canvas, CanvasText, LinkText, ButtonFace and ButtonText**, then compare those values to the actual implemented content, field, ordinary document link, heading punctuation and action roles. Native fields/actions and the skip action use ButtonFace/ButtonText; ordinary document links use LinkText. Actual keyboard focus is checked against CanvasText. Unused root tokens are not evidence for rendered focus. Native checkbox appearance/checked semantics and actual pixels supplement those role checks.

These checks do not establish full accessibility conformance, screen-reader behavior, other browser engines, physical devices, native zoom/text enlargement, intended font-binary metrics, a user study, backend behavior, performance or complete themed application validation.
