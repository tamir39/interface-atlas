# Project examples

The portfolio and agent operations examples are self-contained project specifications derived from Editorial:

- [Portfolio](portfolio/design.md) preserves expressive typography and comfortable reading layouts.
- [Agent operations dashboard](agent-operations-dashboard/design.md) adapts density, geometry, motion, and interaction flow.

Both are drafts for hypothetical requirements. They do not establish that a UI, backend, approval system, or cancellation guarantee has been implemented.

The [Editorial preview](../themes/editorial/preview/README.md) demonstrates representative layouts and local simulation behavior. It does not implement all the requirements of either project example.

Use an example to understand adaptation decisions, not as a universal project requirement. Supply real project content, supported capabilities, language requirements, and evidence before implementation. Retain the example's source credits and update the adaptation record when changing its rules.

The reusable Editorial theme lives in [themes/editorial](../themes/editorial/README.md).

The [workflow evaluation](workflow-evaluation/README.md) separately records a fresh bilingual journal brief and its generated design document. It is evidence about the preparation workflow, not an additional theme.

The [nine-theme coverage assessment](coverage-evaluation/README.md) compares the original five project families and a separate consumer-app case, then records fresh Layered consumer and Gallery storefront design trials. Their briefs, first-generation reading logs, review history and source credits are retained. They are unimplemented project drafts with explicit persistence/service/asset gates. The [skills roadmap](coverage-evaluation/skills-roadmap.md) is a proposal; no skill or shared knowledge chapter was implemented by that evaluation.

The [P0 review and design trials](p0-evaluation/README.md) follow the knowledge research with three fresh generated documents, immutable first drafts, independent findings and one correction pass. Reading logs and capability gates remain explicit; no skill, UI or service is implemented by this evaluation.

The [updated preparation and opt-in review trials](skill-evaluation/README.md) exercise the implemented workflow definitions on the three known briefs and a fresh operations brief, with explicit review, scope probes, retained first drafts and measured source reads. Their records separate document decisions from unperformed product/runtime/usability checks.

The [reference and craft rerun](reference-craft-evaluation/README.md) exercises the A–D knowledge additions on the unchanged consumer, storefront and bilingual-service briefs. It preserves first drafts, independent reviews, reading logs, supported corrections and an isolated synthetic reference probe. These remain document exercises; source inspection and corrected specifications do not establish runtime or usability results.

The [implementation workflow trial](implementation-evaluation/README.md) uses the new skill to add search to the actual Atlas preview hub. Its evidence separates the independent implementation, selective reads and real Chromium checks from unperformed assistive-technology or user research. Earlier design-document trials remain unchanged.

## Visual-style composition

[Glassmorphism composition evaluation](style-composition-evaluation/README.md) compares bounded profiles from all nine current themes, documents default-treatment conflicts and scoped adaptations, and records actual preview checks. Its sample design is an original project proposal, not a production deployment or nine fully revalidated theme applications.

[Neobrutalism composition evaluation](neobrutalism-composition-evaluation/README.md) adds nine bounded theme profiles, selected/error/input-recovery checks and reasoned fit decisions for hard outlines and offset depth. Its original board specimen remains browser-local. A profile pass does not validate the complete themed applications or make a decorative treatment their default.

[Claymorphism composition evaluation](claymorphism-composition-evaluation/README.md) adds nine bounded theme profiles for inflated shells, opaque content faces and explicit shape overrides. Its original creative-practice planner exercises selection, local title/minutes validation, review and recovery. Rendering evidence and source-based fit decisions remain separate; complete themed apps and real-service outcomes are outside this trial.

[Neumorphism composition evaluation](neumorphism-composition-evaluation/README.md) adds nine bounded theme profiles for shallow same-material relief, original-corner geometry and explicit state cues. Its original reading-preset workbench applies real text size, line spacing and line-length changes only after local validation; draft edits and invalid input retain the previously applied specimen. Profile evidence, theme suitability and full-app validation remain separate.

[Skeuomorphism composition evaluation](skeuomorphism-composition-evaluation/README.md) adds a bounded notebook variant across nine theme profiles. Fieldbook preserves per-note page-only drafts, searches applied records, retains hidden open context and downloads the actual applied title/body/tags under a stable filename. Its paper-page geometry and decorative binding are declared artifact choices; other family variants require separate assessment.

[Web Brutalism composition evaluation](web-brutalism-composition-evaluation/README.md) adds a content-first Open Index variant across nine theme profiles. All six original notes remain readable independent of optional index filtering. Native article/history behavior, hidden-selected-note retention and actual UTF-8 reading-plan contents are tested separately from source-based fit judgments and the explicit flat geometry override.

[Flat Design composition evaluation](flat-design-composition-evaluation/README.md) adds the original Next Up local task board across nine bounded theme profiles. Opaque planes, explicit affordances and source corner values remain while decorative depth is removed. Local creation, completion, filtered focus recovery and reload behavior are tested separately from theme fit; no backend or durable task storage is implied.
