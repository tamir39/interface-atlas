# Layered

A spacious application direction built from purposeful opaque tonal planes, friendly geometric sans typography, repeated rounded geometry, and selective elevation. Navigation, working content, supporting context, and a temporary editor have different roles without turning every region into a shadowed card.

Layered is an **original Interface Atlas synthesis for Tamir (Phi Vuong Tuong Tam), prepared with Codex AI assistance**. Google's Material Design 3 supplies conceptual references for surface roles, elevation, shape coherence, adaptive composition, and states. Microsoft's Fluent 2 supplies a separate comparison for opaque material, depth, and readable hierarchy. No design-system implementation, token package, artwork, screenshots, prose, or font software is imported. Every numerical rule and the preview's composition and workflow are Atlas proposals.

This is a complete visual direction rather than a teal palette variant. Editorial emphasizes serif-led reading and publication rhythm; Precision emphasizes compact, flat operational work. Layered gives consumer tasks more room, uses tonal planes to establish context, and reserves raised treatment for a deliberate temporary editor. Neither glass nor continuous motion defines its identity.

## Suitability

These are Atlas design assessments, not measured usability or product outcomes.

| Project type | Fit | Reason and adaptation |
| --- | --- | --- |
| Consumer application | Strong | Comfortable controls and distinct working regions suit ordinary browsing, selection, and editing. Define the actual navigation model and persistence. |
| Personal planner | Strong | Small projects and checklist tasks can remain readable without a dense analytics shell. Real dates, reminders, sync, and recovery need a project contract. |
| Learning workspace | Strong | Spacious task groupings can separate current work, supporting material, and settings. Enrollment, durable progress, assessment, and access remain product decisions. |
| Team project space | Conditional | Tonal composition supports projects and contextual editing. Membership, collaboration conflicts, authority, and audit behavior are not supplied here. |
| Settings interface | Strong | Grouped controls and a restrained modal editor support focused changes. Explain immediate versus saved effects and reversible versus consequential actions. |
| Portfolio or publication | Conditional | Use an application-like index when it helps navigation. Layered's comfortable workspace composition is not a substitute for an image or long-reading system. |
| Dense agent operations | Conditional | Add explicit execution, attention, connection, approval, and pending-command dimensions. A rounded card does not establish an agent's authority or confirmed outcome. |
| Image-led catalog or expressive campaign | Strained | Application surfaces can compete with the primary imagery or poster composition. Gallery or Pulse may provide a more direct starting point. |

Record the selected fit and adaptations in the consuming project's design document. Load [shared Agent Experience guidance](../../knowledge/agent-experience.md) only when relevant to that project's tasks.

## Preview and validation

The [live Layered reference preview](https://tamir39.github.io/interface-atlas/themes/layered/preview/) presents an original fictional **Small plans** workspace. It combines project filtering, native checklist tasks, computed sample-task counts, an inline current project, and a native modal editor with validation, Save, Cancel, Escape, and project-specific Revert. [Preview notes](preview/README.md) define the bounded flow.

[Index.html](preview/index.html) opens locally with its adjacent CSS and JavaScript. There are no remote fonts, scripts, images, accounts, services, or simulated network requests. Only appearance, specimen density, and motion preference persist; project edits and task changes reset on reload. No JavaScript leaves all three project articles readable and runtime controls unavailable with an explanation.

Read [validation.md](validation.md) for actual browser evidence. The arithmetic in [design.md](design.md) is limited to the named opaque color pairs. The theme stays **draft**: representative checks do not establish complete accessibility, every assistive technology, intended-font rendering, real-device performance, collaboration correctness, or production persistence.
