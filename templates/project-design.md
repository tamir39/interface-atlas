## Project requirements and assumptions

Describe the users, essential tasks, real constraints, supported capabilities, and unknowns. Distinguish confirmed requirements from design proposals.

When relevant, resolve languages and translation availability, content/media delivery, and asset ownership or credits.

## Color contract

List every semantic color used, its light/dark values, and permitted pairings. Identify retained source values and new project values.

## Typography, spacing, and geometry

Give selected font families, weights, language coverage requirements, sizes, line heights, spacing, corners, elevation, and data typography where relevant.

## Pages and responsive behavior

Specify content order, layout constraints, adaptive behavior, overflow, and navigation. Use real content needs to justify breakpoints.

## Components, states, and recovery

Specify default, focus, hover, selected, pending, unavailable, empty, and failure behavior where applicable. Include meaningful labels and recovery actions.

## Interaction flows

Describe the key task paths and state changes. Add agent controls or decision flows only when the product needs them.

For stateful features, identify where state lives, what persists, and how failure or undo affects the user's next action.

## Accessibility, motion, and performance

Resolve the required behavior into concrete project rules. Select optional effects explicitly. Include reduced-motion fallbacks and actual loading/rendering constraints.

## Validation

Record performed checks separately from required future checks. Do not claim rendered validation from numerical calculations alone.
